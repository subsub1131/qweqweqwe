# 카카오 로그인 연결하기

## 현재 로컬 검증 상태 — 2026-10-20

`http://127.0.0.1:8000/`에서 실제 카카오계정 인증을 사용자가 직접 완료했고, 서비스 복귀 후 카카오 계정 사용자 카드 표시와 새로고침 후 로그인 유지까지 확인했습니다. 이는 현재 로컬 환경에서의 실제 연동 검증 결과입니다. 아래의 최초 준비 단계 설명과 외부 배포 검증은 구분해서 읽습니다. 운영 Nginx·HTTPS 환경은 검증하지 않았습니다.

서버의 카카오 OAuth 흐름과 새 로그인 화면은 준비되어 있습니다. 실제 카카오 앱 생성·키 등록·외부 배포는 수행하지 않았습니다. 아래 작업은 해당 서비스의 카카오 앱 관리자와 서버 운영자가 진행합니다.

## 1. 로컬 일반 로그인부터 연결

[웹 실행 안내](../web/README.md)에 따라 서버의 기존 `.env`를 보존하면서 새 `SECRET_KEY`(최소 32 UTF-8 바이트), DB, `FRONTEND_URL=http://127.0.0.1:8080`, `COOKIE_SECURE=false`를 설정합니다. 프런트 정적 서버는 8080, FastAPI 백엔드는 8000 포트에서 실행합니다. 브라우저가 백엔드 API를 직접 호출하며 프런트 프록시와 Nginx는 필요 없습니다. `spring-demo/`는 인증 서버가 아닙니다.

먼저 `http://127.0.0.1:8080/`에서 일반 계정 가입·로그인·새로고침·로그아웃을 확인하세요. `/api/auth/me`의 401은 로그인 전 정상 상태입니다.

## 2. 카카오 콘솔에 등록

1. [Kakao Developers](https://developers.kakao.com/)에서 서비스 앱을 선택하거나 새 앱을 만듭니다. 이미 사용 중인 서비스 앱이 있으면 그 앱을 사용합니다.
2. **카카오 로그인 → 사용 설정**에서 상태를 **ON**으로 설정합니다.
3. **앱 → 플랫폼 키 → REST API 키**에서 서버에서 사용할 REST API 키를 확인합니다. JavaScript 키·앱 ID·어드민 키와 혼동하지 마세요.
4. 해당 REST API 키 설정의 **리다이렉트 URI**에 다음 주소를 정확히 등록합니다.

   ```text
   http://127.0.0.1:8000/api/auth/kakao/callback
   ```

5. 같은 REST API 키의 **클라이언트 시크릿** 활성 상태를 확인합니다. 활성화되어 있으면 발급된 값을 서버의 `KAKAO_CLIENT_SECRET`에 반드시 설정합니다. 현재 공식 문서상 새 REST API 키는 기본 활성화될 수 있습니다. 이 서버는 시크릿 전송을 지원하며, 콘솔에서 시크릿 기능을 사용하지 않는 경우에만 값을 비울 수 있습니다.
6. **카카오 로그인 → 동의항목**에서 서비스에 필요한 항목만 설정합니다. 이 구현은 이메일·닉네임이 없어도 카카오 회원번호로 로그인하고 기본 이름을 사용합니다. 이메일을 필수 정보로 요구하거나 일반 계정과 이메일로 자동 연결하지 않습니다.

설정 위치와 정책은 [공식 카카오 로그인 설정 문서](https://developers.kakao.com/docs/ko/kakaologin/prerequisite), [앱 및 플랫폼 키 설정](https://developers.kakao.com/docs/ko/app-setting/app)을 기준으로 확인하세요. 이 연결은 REST API 방식이며 프런트 JavaScript SDK나 JavaScript 키는 사용하지 않습니다.

## 3. 서버에만 설정 저장

기존 `.env`를 덮어쓰지 않고 필요한 행을 추가·수정합니다. 값은 웹 JavaScript·HTML·채팅·스크린샷·Git에 넣지 않습니다.

```dotenv
FRONTEND_URL=http://127.0.0.1:8080
COOKIE_SECURE=false
KAKAO_REST_API_KEY=<해당 앱의 REST API 키>
KAKAO_CLIENT_SECRET=<콘솔에서 활성화된 시크릿 값>
KAKAO_REDIRECT_URI=http://127.0.0.1:8000/api/auth/kakao/callback
```

`SECRET_KEY`와 `ALGORITHM=HS256`도 [웹 실행 안내](../web/README.md)대로 설정되어 있어야 합니다. 수정 후 FastAPI를 재시작하고 화면을 새로고침합니다. `/api/auth/providers`는 `{"kakao":{"enabled":true}}` 같은 준비 상태만 반환합니다. `true`는 로컬 설정 검증 결과이며 실제 키의 유효성·콘솔 설정·카카오 연결 성공을 보장하지 않습니다.

로컬에서는 브라우저 → FastAPI `/api/auth/kakao/login` → 카카오 인가 → FastAPI `/api/auth/kakao/callback` → 프런트 루트 순서입니다. URI는 카카오 콘솔·`.env`에서 프로토콜·호스트·포트·경로가 일치해야 합니다. 로컬 콜백에도 /api 접두사를 포함합니다. Nginx를 별도로 사용하는 배포 환경에서는 외부 공개 주소를 등록합니다.

## 4. 실제 계정으로 확인할 항목

- 노란색 **카카오 로그인** 버튼을 누르면 카카오의 실제 인가 화면이 열리는지 확인합니다.
- 동의 후 프런트 루트의 사용자 카드에 **카카오 계정**이 표시되는지 확인합니다.
- 새로고침 시 로그인 상태가 복원되고 로그아웃 후 로그인 화면으로 돌아오는지 확인합니다. 같은 카카오 계정으로 다시 로그인해 기존 계정이 복원되는지도 확인합니다.
- 동의를 취소했을 때 한국어 안내가 나오고 다른 로그인 방법을 계속 사용할 수 있는지 확인합니다.
- 닉네임·이메일 제공에 동의하지 않아도 로그인이 가능한지 확인합니다.

이번 작업은 모의 API·임시 DB 검증까지 수행했습니다. 위 실제 계정 검증과 Nginx 운영 검증은 남아 있습니다. 로그아웃 버튼은 qwer 세션을 종료하며 카카오 계정 전체 로그아웃이나 앱 연결 해제를 수행하지 않습니다.

카카오 로그인 시작 시 항상 `prompt=login`을 전송합니다. 따라서 로그아웃 후 다시 로그인하면 브라우저에 카카오 세션이 남아 있어도 카카오계정 로그인 화면에서 다시 인증합니다. 별도 `login_hint`로 기존 계정을 지정하지 않습니다. 카카오 공식 문서상 `prompt=login`은 카카오톡 인앱 브라우저에서는 지원되지 않습니다.

2026-10-20 최종 리뷰 보완 후 전체 인증 테스트 42개가 통과했습니다. 삭제된 계정 번호가 재사용되어도 이전 JWT로 다른 계정에 접근할 수 없도록 계정 확인값을 검증합니다. 변경 전 발급된 JWT는 다시 로그인해야 합니다. 인증 입력 오류 응답의 비밀번호 노출과 비정상 카카오 토큰 처리도 보완했습니다.

## 5. 오류 확인

| 증상 | 확인할 설정 |
| --- | --- |
| 버튼이 준비 중 상태 | REST API 키, Redirect URI, 유효한 SECRET_KEY, FRONTEND_URL 설정 후 백엔드 재시작 |
| 버튼 상태 확인 실패 | Nginx `/api/` 프록시, FastAPI 실행 상태, 네트워크 연결 |
| `KOE004` | 카카오 로그인 상태 ON 여부 |
| `KOE006` | 콘솔 URI와 서버 URI의 정확한 일치 여부 |
| 인가 후 완료하지 못했다는 안내 | REST API 키 종류·해당 키의 활성 Client Secret·카카오 연결 상태 |
| 요청 검증 오류 | 로그인 시작부터 다시 진행; state 유효기간 10분, 쿠키 차단·다중 탭·주소 변경 여부 |
| 로그인 후 상태가 유지되지 않음 | 접속 호스트 일치, 쿠키 허용, HTTP에서 COOKIE_SECURE=false 여부 |
| 일반 로그인 POST가 403 | 브라우저 Origin과 FRONTEND_URL의 프로토콜·호스트·포트 일치 여부 |

서버는 `kakao_cancelled`, `invalid_state`, `kakao_unavailable`, `kakao_failed`만 프런트 URL로 전달하며 화면은 읽은 뒤 URL에서 제거합니다. 카카오 응답 본문·인가 코드·토큰은 사용자 안내로 반사하지 않습니다.

## 6. 운영 HTTPS

운영 프런트 주소를 HTTPS로 정하고 Nginx TLS를 설정합니다. `FRONTEND_URL=https://서비스도메인`, `COOKIE_SECURE=true`, `KAKAO_REDIRECT_URI=https://서비스도메인/api/auth/kakao/callback`로 변경하고 카카오 콘솔에도 같은 콜백을 등록합니다. 강한 SECRET_KEY를 서버 비밀 저장소에서 관리하고 기본 개발 값을 재사용하지 않습니다. 키를 바꾸면 기존 세션은 다시 로그인해야 합니다.

카카오 버튼의 노란 배경·검정 말풍선·문구는 [공식 디자인 가이드](https://developers.kakao.com/docs/ko/kakaologin/design-guide)를 따릅니다.
