# 신규 로그인 화면 및 카카오 로그인 준비 설계

작성일: 2026-10-20

## 목적과 확정 범위

사용자는 기존 화면을 모두 삭제하고 새로운 로그인 화면을 구성하며, Superpowers를 사용하여 카카오 로그인까지 준비하도록 요청했다. 기존 화면 전체 교체 방향은 대화에서 승인되었다.

기존 `web/index.html`, `web/styles.css`, `web/app.js`, `web/README.md`의 내용을 폐기하고 같은 위치에 새 로그인 전용 프런트엔드를 구성한다. 게시판, 사이드바, API 응답 패널, 연결 설정 팝업, 기존 회원 팝업은 새 화면에 포함하지 않는다. 같은 경로를 사용하는 이유는 현재 Nginx 정적 파일 배포 방식을 유지하기 위해서다.

삭제 범위는 기존 웹 화면 전체이다. 로그인 연동에 필요한 FastAPI 코드와 데이터베이스, `.env`, Java 데모 및 배포 도구는 화면 삭제 대상에 포함하지 않는다. 실제 사용자 데이터 삭제, 외부 배포, 카카오 앱 생성은 이번 작업에 포함하지 않는다.

## 접근 방식

추천안은 기존 FastAPI를 인증 서버로 사용하고 순수 HTML/CSS/JavaScript로 화면을 새로 만드는 것이다. 기존 배포 구조를 활용하면서 서버에서 카카오 인가 코드와 토큰을 처리할 수 있다.

대안은 로그인 UI와 카카오 버튼만 준비하는 방식이다. 변경은 작지만 실제 로그인 연결 코드가 남아 사용자의 '카카오 로그인까지 준비' 요구를 충분히 충족하지 못한다. React 등 별도 프런트 프레임워크 도입은 이번 로그인 화면의 규모에 비해 빌드·배포 변경이 커서 채택하지 않는다.

## 새 화면

- 데스크톱: 서비스 소개 영역과 로그인 카드의 2열 구성. 모바일: 로그인 중심의 단일 열.
- 시각 방향: 밝은 배경, 짙은 글자, 녹색 포인트, 충분한 여백. 기존 게시판 레이아웃을 재사용하지 않는다.
- 로그인 카드: 아이디, 비밀번호, 비밀번호 표시 전환, 로그인 버튼, 노란색 카카오 로그인 버튼.
- 기존 회원가입 API를 사용하는 회원가입 모드를 같은 카드에 제공한다. 이름·아이디·이메일·비밀번호를 입력하고 가입 후 로그인 모드로 돌아간다.
- 키보드 탐색, 명시적인 입력 라벨, 자동완성 속성, 제출 중 중복 클릭 방지, 한국어 오류 안내를 제공한다.
- 로그인 성공 시 같은 페이지에서 사용자 이름·로그인 방식·로그아웃 버튼을 보여준다. 삭제된 게시판으로 이동하는 링크는 만들지 않는다.
- 새로고침 시 서버의 현재 로그인 정보로 화면을 복원한다. 비밀번호·JWT·카카오 토큰은 화면 또는 localStorage에 저장하지 않는다.

## 일반 로그인과 공통 세션

기존 `/user/signUp`, `/user/login`의 요청 필드는 유지하되 비밀번호가 포함된 응답은 제거한다. 로그인은 실제 저장된 비밀번호를 검증하며 실패 시 아이디 존재 여부를 구분하지 않는 HTTP 401을 반환한다.

신규 비밀번호는 salt를 사용하는 scrypt 해시로 저장한다. 기존 평문 계정은 올바른 비밀번호로 로그인한 경우에만 해시로 갱신한다. 기존 사용자의 비밀번호를 추측해 일괄 변환하거나 실제 DB를 테스트 대상으로 사용하지 않는다. 세션은 요청 단위 의존성으로 닫는다.

새 서비스 JWT는 로그인 방식과 내부 식별자를 구분하는 subject를 사용하고 만료 시간을 검증한다. 서버가 허용한 알고리즘으로만 검증한다. 카카오 회원번호와 일반 회원 아이디가 같아도 다른 사용자로 처리한다. 기존 JWT는 새 로그인으로 갱신하도록 한다.

최종 검토 보완: SQLite의 계정 번호 재사용으로 삭제된 계정의 JWT가 새 계정을 인증하지 못하도록 계정 바인딩을 필수로 검증한다. 일반 계정은 최종 저장된 salted 비밀번호 해시와 계정 식별값의 keyed fingerprint, 소셜 계정은 provider 회원 식별값으로 바인딩하며 DB를 재구축하지 않는다. 바인딩이 없는 이전 토큰은 거부한다. 인증 입력 검증 오류에서도 원문 input과 민감 context를 제거해 비밀번호가 422 응답에 포함되지 않게 한다.

`GET /auth/me`는 최소 사용자 정보와 로그인 방식을 반환하며 세션이 없거나 만료되었으면 401을 반환한다. `POST /auth/logout`은 서비스 쿠키를 만료시킨다. 이는 카카오 계정 전체 로그아웃이나 연결 해제 기능이 아니다. 세션 조회는 캐시하지 않는다.

쿠키는 HttpOnly, SameSite=Lax, Path=/, JWT와 일치하는 유효기간을 사용한다. Secure는 환경설정으로 제어하며 로컬 HTTP와 배포 HTTPS의 차이를 문서화한다. 기존 JWT 기본 키는 새 인증에서 사용하지 않도록 명시적인 키 설정을 요구한다. 상태를 변경하는 요청의 Origin을 설정된 프런트 origin과 검증한다.

## 카카오 로그인

브라우저는 같은 origin의 `/api/auth/kakao/login`으로 이동한다. Nginx는 기존 규칙대로 `/api/`를 제거한다. FastAPI의 `GET /auth/kakao/login`은 임의의 state와 만료되는 HttpOnly 쿠키를 만들고 카카오 인가 화면으로 이동시킨다.

`GET /auth/kakao/callback`은 state와 쿠키의 일치·만료를 먼저 확인하고 일회성 흐름 쿠키를 삭제한다. 성공한 인가 코드를 서버에서 토큰으로 교환하고 사용자 정보 API로 검증된 카카오 회원번호를 조회한다. 임의의 브라우저 전달 사용자 정보는 인증 근거로 사용하지 않는다.

별도 소셜 계정 테이블에 카카오 회원번호를 고유하게 저장한다. 동시 최초 로그인에도 중복 계정을 생성하지 않는다. 이메일은 필수로 요구하지 않으며, 같은 이메일의 일반 계정과 자동으로 연결하지 않는다. 닉네임이 없으면 기본 표시 이름을 사용한다. 카카오 토큰은 프로필 조회에만 사용하고 DB·브라우저에 저장하지 않는다.

성공 시 서비스 JWT 쿠키를 발급하고 설정된 프런트 루트로 이동한다. 취소·state 오류·카카오 통신 실패는 사전에 정한 오류 코드로 로그인 화면에 돌아와 한국어로 안내한다. 외부 응답 본문·인가 코드·토큰은 URL이나 화면에 노출하지 않는다. 임의의 return URL을 받지 않는다. 서버의 외부 HTTP 요청에는 타임아웃을 적용한다.

## 설정과 배포

`.env.example`에 `DATABASE_URL`, `SECRET_KEY`, `ALGORITHM`, `FRONTEND_URL`, `COOKIE_SECURE`, `KAKAO_REST_API_KEY`, `KAKAO_CLIENT_SECRET`, `KAKAO_REDIRECT_URI`를 설명한다. 기존 `.env`는 덮어쓰거나 비밀값을 보고서에 기록하지 않는다.

카카오 키가 없을 때 일반 로그인 화면과 API는 사용할 수 있어야 한다. 화면은 설정 상태 API로 카카오 사용 가능 여부를 확인하고, 미설정 상태의 카카오 버튼은 비활성화한다. 설정 상태 API는 키·시크릿을 반환하지 않는다.

`web/README.md`를 새 화면 기준으로 다시 작성하고 별도 카카오 설정 가이드를 제공한다. 카카오 개발자 앱의 로그인 활성화, REST API 키, 선택적 Client Secret, 등록한 Redirect URI와 서버 설정의 일치, HTTPS 운영 설정을 안내한다. 실제 키가 없는 상태에서는 모의 통신 검증까지 수행하며 실제 카카오 로그인 성공으로 보고하지 않는다.

Python 의존성 파일에는 실제 사용하는 SQLAlchemy·PyJWT 등 누락된 런타임 의존성을 반영한다. 새 프런트엔드는 Node 빌드나 외부 CDN을 요구하지 않는다.

## 검증 및 완료 조건

- 임시 SQLite DB와 모의 카카오 HTTP 응답을 사용해 실제 데이터에 접근하지 않는다.
- 일반 로그인 성공·잘못된 비밀번호·존재하지 않는 아이디·해시 저장·기존 평문 계정 전환·비밀번호 응답 제외를 검증한다.
- 카카오 키 미설정, 인가 URL, state 누락·불일치·만료, 사용자 취소, 토큰 교환 실패, 사용자 조회 실패, 최초·반복·중복 로그인, 이메일 미제공을 검증한다.
- 세션의 만료·서명 오류·회원 삭제·로그아웃과 Origin 검증을 확인한다.
- 새 프런트의 데스크톱·모바일 레이아웃, 키보드 입력, 로그인 실패, 중복 제출 방지, 로그인 상태 복원, 카카오 오류 안내를 확인한다.
- 기존 게시판 화면과 관련 DOM·스크립트가 새 웹 파일에 남아 있지 않아야 한다.
- 실제 카카오 로그인은 사용자의 앱 설정 및 키 등록 이후에 별도로 검증한다.
