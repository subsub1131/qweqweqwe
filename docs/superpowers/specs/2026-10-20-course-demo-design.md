# 온라인 강의 시연 — 최소 범위

사용자는 강사1명·수강생 구조의 온라인 강의 사이트를 요청했고, 실제 결제·권한·DB 변경 대신 단순 보여주기 시연으로 축소하여 진행하도록 지정했다. 기존 벚꽃 로그인과 카카오 인증, 프런트8080→백엔드8000 직접 통신은 유지한다.

## 시연 기능

- 강의 목록: 샘플4개, 제목·분류·가격·강사 표시.
- 강의 상세: 소개·분량·수업 수·가격, 테스트 구매 버튼.
- 상품 등록: 강사 체험 폼에서 제목·설명·분류·가격·분량·수업 수 입력. 등록 API는 로그인 확인만 한다. 실제 회원별 강사 권한은 미구현이며 화면에도 시연임을 표시한다.
- 구매: 로그인 회원이 테스트 구매 버튼을 누르면 즉시 구매 완료. 실제 결제나 카드 입력 없음. 가격은 서버 상품 기준, 중복 구매는 같은 결과 반환.
- 내 강의: 로그인 회원의 시연 구매 목록 표시.

상품·구매는 프로세스 메모리에만 저장하고 서버 재시작 시 초기화한다. 기존 DB 모델과 테이블은 수정하지 않는다. DB 설계 공유 후 저장소를 교체한다. 강사는 표시용 이름 한 명이며 권한 테이블·PG·영상 업로드/재생·수강 진도·환불·장바구니는 제외한다.

## API 계약

Course: `{id:int,title:str,description:str,category:str,price:int,duration_minutes:int,lesson_count:int,instructor:str}`. 강사 표시명은 서버가 고정한다.

- `GET /api/courses` → `{items:Course[]}`
- `GET /api/courses/{id}` → Course, 없으면404
- `POST /api/demo/courses` → Course(201), 요청은 id/instructor를 제외한 Course 필드. 로그인·Origin 확인, 유효성 검증.
- `POST /api/demo/purchases` `{course_id:int}` → `{id:str,course:Course,demo:true}` (최초201/재구매200), 로그인·Origin 확인.
- `GET /api/my/courses` → `{items:Course[]}`, 로그인 확인.

기존 HttpOnly 인증을 사용하고 가격·사용자 정보는 프런트 값을 신뢰하지 않는다. 계정별 구매 구분에는 서버에서 기존 계정 확인값을 사용한다. 상품 ID는 증가 정수, 구매 ID는 UUID. 기존 통신 메타데이터 로그 유지.

## 역할·실행

프런트/백엔드는 각각 별도 Git worktree. 프로젝트의 `.codex/agents` 개발지침을 전달한다. 설정의 모델명이 유효하지 않으므로 모델파일을 임의 수정하지 않고 현재 세션에서 지원되는 기본 모델을 상속한다.

프런트는 courses.html과 api/assets/components/router/stores/views 모듈, 로컬 Axios로 백엔드 절대주소 직접 호출. 기존 로그인 페이지에 강의 페이지 링크를 넣는다. 과도한 프레임워크나 빌드 시스템은 도입하지 않는다. 벚꽃 스타일과 모바일 대응 유지.

백엔드는 상품/구매 메모리 저장소, 라우터, 회귀 테스트 담당. 메인은 API 계약·Git 기준점·병합·최종 확인 담당.

검증은 임시 SQLite 인증+메모리 상품으로 API 테스트, 모의 API 화면 테스트, Chrome 시연 흐름 확인으로 한정한다. 실제 사용자 DB에 테스트 계정을 만들지 않는다.
